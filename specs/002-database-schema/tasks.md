# Tasks: Database Schema & Migrations

**Input**: Design documents from `/specs/002-database-schema/`

**Prerequisites**: plan.md (required), spec.md (required), research.md, data-model.md, contracts/queries.md, quickstart.md

**Tests**: Integration tests against real Postgres are included (test-first per Constitution principle IV).

**Organization**: SPEC-02 is a slim (infrastructure) spec. Tasks are grouped by logical phase (setup, foundational migration, sqlc queries, tests, polish) rather than user stories. Each phase has a checkpoint.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (N/A for infrastructure spec)
- Include exact file paths in descriptions

## Path Conventions

- **Single Go binary**: `migrations/`, `internal/db/` at repository root
- Migrations: `migrations/` (golang-migrate convention)
- sqlc queries: `internal/db/queries/` (sqlc input)
- sqlc generated: `internal/db/` (gitignored, regenerated by `make sqlc`)
- Tests: `internal/db/db_test.go` (integration tests against real Postgres)

## Phase 2: Foundational (Initial Schema Migration)

**Purpose**: Create the forward-only SQL migration with all 8 tables. This is the core deliverable of SPEC-02.

**CRITICAL**: No other phase can begin until this migration exists and `migrate up` succeeds.

- [ ] T003 Create `migrations/000001_initial_schema.up.sql` -- CREATE TABLE for all 8 tables in FK dependency order: tenants, users, sessions, properties, clients, prospections, contacts, audit_log. Follow data-model.md exactly: UUID PKs with `gen_random_uuid()` default, `tenant_id` FK + index on all 7 tenant-scoped tables, `created_at`/`updated_at` timestamps, `deleted_at` soft-delete on tenants/users/properties/clients/prospections/contacts, CHECK constraints (users.role 6 values, properties.status 4 values, properties.type 4 values, clients.status 3 values, prospections.status 6 values, contacts.channel 4 values, contacts.direction 2 values), UNIQUE constraints (users tenant_id+email, sessions token_hash). Create all indexes: `idx_<table>_tenant_id` on all 7 tenant-scoped tables, plus `idx_users_tenant_email`, `idx_sessions_token_hash`, `idx_properties_status`, `idx_properties_type`, `idx_clients_status`, `idx_prospections_client_id`, `idx_prospections_property_id`, `idx_prospections_status`, `idx_contacts_client_id`, `idx_contacts_prospect_id`, `idx_audit_log_entity`. (FR-001, FR-002, FR-003, FR-004, FR-005, FR-006, FR-007, FR-008, FR-009, data-model.md)
- [ ] T004 Create `migrations/000001_initial_schema.down.sql` -- DROP TABLE in reverse FK dependency order: audit_log, contacts, prospections, clients, properties, sessions, users, tenants. Use `DROP TABLE IF EXISTS ... CASCADE` for safety. (FR-001, data-model.md)

**Checkpoint**: `migrate up` against a fresh test DB succeeds. `psql -c "\dt"` lists all 8 tables + `schema_migrations`. Run: `createdb prospeccaobrasil_test && migrate -path migrations -database "postgres://postgres:postgres@localhost:5432/prospeccaobrasil_test?sslmode=disable" up && psql -d prospeccaobrasil_test -c "\dt"`.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies -- can start immediately.
- **Foundational (Phase 2)**: Depends on Setup (T001, T002) -- BLOCKS all other phases.
- **sqlc Queries (Phase 3)**: Depends on Foundational (T003, T004). All query tasks (T005-T012) are parallel. T013 (make sqlc) depends on all query tasks.
- **Integration Tests (Phase 4)**: Depends on Phase 3 (T013 -- sqlc generated code must exist). Test tasks T015-T022 are parallel. T023 depends on all entity tests. T024 depends on T023.
- **Polish (Phase 5)**: Depends on Phase 4 (T024). Sequential.

### Parallel Opportunities

- Phase 1: T001 and T002 can run together (both `go get`).
- Phase 3: T005-T012 (8 query files) can all run in parallel.
- Phase 4: T015-T022 (8 entity tests) can all run in parallel.
